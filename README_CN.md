# GHV

[English](README.md)

**GHV** 是一个实验性的开放视频 / 音频格式项目，核心围绕四个目标：

- **更小的文件体积**
- **更高的画质与音质**
- **更快的编码与解码**
- **开放、可扩展、广泛兼容的实现方式**

项目目前仍在快速开发中，最新的视频编码核心迭代为 **GHVC8**。

## 当前项目组成

GHV 不只是一个文件扩展名，而是在逐步形成一套小型媒体栈：

- **GHV** — 容器 / 视频格式方向。
- **GHVC8** — 当前视频编码核心。
- **GHA** — 配套音频格式。
- **原生解码器** — 基于 C++17 的高性能解码路径。
- **验证工具** — 用来区分“文件损坏”和“播放器性能跟不上”。
- **基准测试工具** — 用来持续追踪每一代编码器与解码器的性能变化。

由于格式仍在快速迭代，目前不同开发代之间还不保证码流兼容。

## 为什么还要做一种新格式？

长期目标不是简单“再做一个自定义 codec”，而是探索一种更均衡的媒体格式：

1. 文件尽量小；
2. 感知画质尽量高；
3. 软件解码尽量轻量；
4. 编码速度尽量快；
5. 容易集成到游戏引擎、播放器和开源软件；
6. 格式可以被公开实现，而不是依赖封闭或专有生态。

所以 GHV 的开发不会只看“能不能编码、能不能播放”，而会持续做文件体积、画质、编码速度、解码速度和播放稳定性测试。

## 当前 GHVC8 基准快照

下面的数据来自当前 GHVC8 开发线。它们**不是在宣称 GHV 已经超过成熟格式**，而是用来真实展示项目现在做到什么程度、还差在哪里。

| 测试 | GHV 结果 | 编码速度 | 解码速度 | 备注 |
| --- | ---: | ---: | ---: | --- |
| Test A | 303,023,656 bytes（约 289 MiB） | 140.44 fps | 448.17 fps | 固定对比样本 |
| Test B | 580,797,129 bytes | 45.46 fps | 141.19 fps | 更重的对比样本 |
| Test C（4K） | — | 9.78 fps | 30.21 fps | 完整播放 PASS；7 drops；0 freezes |

### Test A 文件体积对比

| 格式 | 约输出体积 | 相对当前 GHV |
| --- | ---: | ---: |
| MP4 对比编码 | ~24.6 MB | 明显更小 |
| OGV 对比编码 | ~45.2 MB | 明显更小 |
| GHV / GHVC8 | 303,023,656 bytes（约 289 MiB） | 基准 |

这里最重要的结论是：**当前 GHVC8 的文件体积仍然远大于 MP4 和 OGV 的对比结果**。压缩率依然是目前最主要、最没有完成的方向之一。

另一方面，当前原生解码器在测试中的纯软件解码吞吐已经比较强，所以接下来的重点就是尽量在不牺牲这部分性能的前提下，把文件体积持续压下来。

> 实际基准会受到源视频、分辨率、质量设置、硬件和具体命令影响。首个公开源码版本会附上可复现的测试脚本与命令。

## 当前开发方向

### 压缩率

目前仍在继续优化预测、残差表达、块描述和更适合熵编码的数据布局。

目标不是单纯追求极限压缩比：任何新的压缩方式都必须同时考虑解码复杂度。

### 解码性能

GHV 的一个核心目标是保持轻量的软件播放路径。

当前开发线已经包含原生 **C++17 解码器**，Python 版本主要保留用于兼容、测试与开发工具链。

### 稳定性与诊断

项目中加入了专门的验证和基准工具，用来判断问题到底出在文件本身还是播放端性能。

这对于 4K 内容和低性能设备测试尤其重要。

### 音频

**GHA** 会与 GHV 一起发展，而不是把音频当成后续附加功能。

## 对比思路

GHV 经常拿 MP4 工作流和 OGV 做对比，因为它们代表了两种很不同的实际参考方向。

| 方向 | GHV 目标 | MP4 生态 | OGV / Theora 生态 |
| --- | --- | --- | --- |
| 文件体积 | 继续大幅降低当前代体积 | 现代 codec 下通常非常高效 | 技术较老，通常比现代 MP4 工作流更大 |
| 画质 | 在实用体积下保持高感知质量 | 现代 codec 表现很强 | 可用，但技术代际较老 |
| 软件解码 | 尽量轻量且高速 | 很依赖具体 codec 与硬件加速 | 纯软件解码相对直接 |
| 开放性 | 开放规范、开放实现 | 容器开放，但具体 codec 的授权情况不同 | 开放且适合自由实现 |
| 集成目标 | 容易进入引擎和工具链 | 生态支持极广 | 对开源软件非常友好 |

这张表描述的是**设计目标与生态差异**，不是在说 GHV 当前已经全面超过其中任何一种格式。

## Roadmap

在首个稳定格式规范之前，主要工作包括：

- 继续推进 GHVC8 之后的压缩优化；
- 缩小当前基准中暴露出的巨大体积差距；
- 保持甚至继续提升原生解码速度；
- 提升高分辨率和 4K 播放稳定性；
- 完善 GHA 音频方向；
- 正式文档化码流 / 容器结构；
- 提供可复现的 MP4 / OGV / GHV 对比脚本；
- 发布 encoder、decoder、verify、benchmark 工具；
- 测试游戏引擎和媒体播放器的集成路径。

## 项目状态

GHV 目前仍属于**实验性项目**。编码核心和容器还在持续迭代，不应该被当成长期归档格式使用。

第一个真正公开的开发版本会包含实际实现，以及足够复现公开测试数据的文档和工具。
