# GHV 0.9 / GHVC9 Bitstream Specification

Status: experimental development profile. GHV container layout, 64-bit index
offsets, frame headers, CRC semantics, GHAC1, I-frame `GTC7`, and Repeat frames
are unchanged from GHV 0.8. This document defines GHVC9 P frames and the optional GIC9 I-frame syntax.

## Design goals

GHVC9 Milestone 1 reduces coefficient rate and full-RD work without increasing
quantization. It retains GHVC8 16x16 even-pixel motion compensation, median MV
delta syntax, 8x8 transform, reconstruction, CRC, and quality tables.

## Optional GIC9 keyframes

With `--compact-coefficients`, the encoder can write a smaller `GIC9`
I payload. Its first 16 bytes and three-bit predictor descriptors follow GTC7,
with the four-byte magic replaced by GIC9. One LSB-first bitstream follows
the descriptor map. Empty blocks consume no bits. Each remaining block emits
its six-bit last index followed by the GBP9 capped-unary zero runs and signed
compact levels (bit 3 syntax below). Use k=4 at zig-zag index zero and k=2 at every
other index. End the stream on a byte boundary with zero padding. The decoder
checks each block endpoint and the exact end of the payload. GIC9 requires a
decoder supporting compact intra frames. Independent keyframe decoding, the
index and reconstructed CRCs use the existing GHV rules.

## P payload header

Integers are little-endian. A normal GHVC9 P payload begins with `GBP9`:

| Offset | Type | Meaning |
|---:|---|---|
| 0 | char[4] | `GBP9` |
| 4 | u8 | motion block size, 16 |
| 5 | u8 | quality, 1..100 |
| 6 | u8 | even-pixel search range |
| 7 | u8 | GBP9 feature bits (M1 writes zero): bit 0 compact motion, bit 1 DC-only end position, bit 2 contextual Rice levels, bit 3 nonzero level offset |
| 8 | u32 | reconstructed YUV420 byte count |
| 12 | u32 | total 8x8 transform block count |
| 16 | u32 | 16x16 motion-vector count |
| 20 | u32 | motion-body byte count |

The delta-coded motion body and one-bit zero-residual descriptor map immediately
follow and are identical to GTP8. Encoder presets change candidate search effort
only; a decoder has no preset-specific behavior.

With `ghvenc --codec 9 --compact-motion`, the encoder may set bit 0
when it saves bytes. Such frames require a decoder built with compact motion
support. The default encoder clears all feature bits. GTP9 retains the M1 syntax.

When bit 0 is set, split the raster-order motion vectors into groups of eight across
row boundaries. Each group starts with a mask, least significant bit first.
Clear bits select the existing median predictor. Set bits have a literal in
vector order. A literal stores zigzag dx in the low nibble and zigzag dy in the
high nibble, each in 0..14. A byte of 255 escapes to two unsigned bytes (dx,
dy in zigzag form), each at most 48 and at least one at least 15. Other
literals containing nibble 15 are reserved. Unused bits of the last mask are
zero. Reconstructed vectors obey the original range and parity constraints.
The declared motion-body length must be consumed exactly.

## Chunk table

Coefficients are divided into consecutive groups of 256 transform blocks.
After the descriptor map:

1. `u32 chunk_count`, exactly `ceil(block_count / 256)`;
2. `chunk_count` little-endian `u32` compressed byte sizes;
3. the byte-aligned chunk payloads in order.

All counts, additions, and payload boundaries must be validated before decode.
Each chunk is independently bit-decodable and may be parsed in parallel.

## Coefficient bits

Zero-residual blocks consume no coefficient bits. Every nonzero block writes:

- 6-bit zig-zag last-index/EOB;
- repeated `(zero_run, signed_level)` pairs until EOB.

`zero_run` uses capped unary: runs 0..6 are `run` zero bits followed by one;
larger runs write seven zero bits, one, then the 6-bit run value.

The nonzero signed level is zig-zag mapped to an unsigned integer and coded by
Rice `k=2`. Quotients 0..30 are unary followed by two remainder bits. Larger
values write quotient escape 31 followed by the full 32-bit zig-zag value.
Unused bits at a chunk end are zero padding.

`--compact-coefficients` permits the encoder to select coefficient flags per GBP9 P frame. These flags require an updated decoder.
For bit 1, read one bit before each nonzero block's end position. Zero denotes
last index 0 and one introduces the usual six-bit last index. For bit 2,
use Rice k=3 for the token at zig-zag index zero and k=1 elsewhere, including
a first token preceded by a nonzero run. When bit 3 is clear the escape
threshold is quotient 31. With bit 3 set, subtract one from the nonzero zig-zag value before
splitting it into quotient q and k remainder bits. For q below 4 write q zero
bits and a one. Otherwise write four zeros and encode n=q-3: write
floor(log2(n)) zeros, a one, then the low floor(log2(n)) bits of n. Append
the original k remainder bits in both cases. All fixed-width fields are
LSB-first. The reconstructed zig-zag level must be in 1..2^20.

GBP9 bit 4 selects an alternate zero-run code. Runs 0..2 retain the original
unary prefix. For run >=3 write three zero bits and set n=run-2. Write
floor(log2(n)) zeros, one, then the low floor(log2(n)) bits of n, LSB-first.
The result must fit the remaining positions in the block. Bits 5..7 are
reserved. The encoder selects bit 4 only with compact coefficients enabled
and when its measured savings exceed seven bits per chunk. Older binaries
that predate bit 4 require files written without that feature.

## Search presets

Presets do not alter syntax or quantization rules:

- Fast: zero motion plus one sampled-SAD finalist, with the existing Fast
  quality/search settings;
- Balanced: zero motion plus the best sampled-SAD nonzero finalist;
- Quality: zero motion plus up to three nonzero finalists.

All finalists use exact reconstructed rate-distortion evaluation and the same
branch-and-bound rule before selection.

## Compatibility and failure behavior

Codec ids 4 through 8 retain their existing decoders. GHVC9 uses the existing
GHV frame index, CRC-32 of the reconstructed frame, 64-bit container offsets,
seek, EOF, and repair rules. A decoder must reject truncated motion data,
invalid chunk counts/sizes, invalid unary/Rice codes, out-of-range runs, payload
trailing bytes, invalid dimensions, or reconstructed CRC mismatch.
